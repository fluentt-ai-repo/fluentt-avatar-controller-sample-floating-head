# v0.3.4 - 미러(반사) 눈 본 Look Target 추적 복구 (Universal Eye-Aim)

**릴리스 날짜**: 2026-06-29

음수 스케일로 미러링된 눈 본(reflected eye bone)에서 한쪽 눈만 좌우 추적 시 시선축으로 심하게 roll(뒹굴뒹굴)하던 문제를 수정했습니다.

> 본 수정은 `AvatarControllerSample` v0.3.3과 동일한 변경을 FloatingHead 변형에 적용한 것입니다. 원 분석·구현·실측 검증은 MarketonProjectDemo에서 `AvatarControllerSample` 기준으로 수행됐습니다. **FloatingHead 변형은 별도 플레이모드 검증이 필요합니다.**

## 근본 원인

일부 리그는 오른쪽 눈 본이 **음수 스케일(반사, 좌수 좌표계)** 로 제작됩니다. `MultiAimConstraint`의 world-up twist 해법은 **오른손 좌표계를 가정**하므로 반사 본을 조준하지 못하고, 좌우 이동이 시선축 둘레 roll로 흡수됩니다. v0.3.3(=ACS 기준)의 `autoDetectEyeAimAxis`(회전 기반)로도 해결 불가(약 20° 잔차).

## 해결책 — Universal Eye-Aim + 자동판별 하이브리드 (`EEyeAimMode`)

`MultiAimConstraint` 대신, 레스트(bind) 포즈에서 눈의 시선/업 방향을 눈 로컬 공간으로 1회 측정해 두고 매 프레임 `LateUpdate`에서 눈 본을 직접 회전시키는 솔버를 추가했습니다. 측정값에 본의 스케일·미러가 흡수되어 축/스케일/미러 무관하게 동작합니다.

성능/회귀를 고려해 3-모드 enum으로 구현:

- **`Auto`(기본)**: init에서 반사 여부(`localToWorldMatrix.determinant < 0`) 감지 → 미러 본이 하나라도 있으면 두 눈 모두 직접구동(좌우 일관성 유지), 정상 리그는 기존 `MultiAimConstraint` 경로 유지(무회귀)
- **`Constraint`**: 항상 컨스트레인트 경로(+ `autoDetectEyeAimAxis`)
- **`DirectUniversal`**: 항상 직접구동

`Transform`/`TransformCorrected` 전략에만 적용, `BlendWeightFluentt`·머리(head)는 영향 없음. 직접구동 활성 시 눈 컨스트레인트 `weight=0`, `Start`에서 1회 보정.
