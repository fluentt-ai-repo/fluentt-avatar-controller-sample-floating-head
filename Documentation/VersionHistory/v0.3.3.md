# v0.3.3 - Look Target 눈 좌우(yaw) 추적 복구

**릴리스 날짜**: 2026-06-26

Transform 계열 눈 추종에서 좌우(yaw) 시선이 거의 움직이지 않던 문제를 수정했습니다. "꼬인(twisted)" 리그 — 눈 본의 로컬 +Z가 실제 시선 방향과 다르게 정렬된 아바타 — 에서 좌우 추적이 동작하지 않던 근본 원인을 해결합니다.

> 본 수정은 `AvatarControllerSample` v0.3.2와 동일한 변경을 FloatingHead 변형에 적용한 것입니다. 원 수정은 mirabel-webgl 프로젝트에서 `AvatarControllerSample` 기준으로 플레이모드 실측 검증을 마쳤습니다(수렴 후 좌우 시선 오차 0.0°). **FloatingHead 변형은 별도 플레이모드 검증이 필요합니다.**

## 근본 원인

`MultiAimConstraint`는 `aimAxis`(기본값 `+Z`)를 시선축으로 가정합니다. 그러나 일부 아바타의 눈 본은 로컬 +Z가 시선축이 아닙니다(예: 로컬 +Z가 "아래", 실제 시선은 로컬 +Y로 조준축이 시선축과 약 90° 어긋남). 이 경우 `worldUpType=None`에서는 조준축 둘레 roll이 미제어되어, 타겟의 좌우 이동이 **시선축 둘레 roll(눈 굴림)** 로 흡수되고 시선에는 반영되지 않습니다. 상하 추적만 우연히 동작하던 상태였습니다.

기존 `UpdateEyeVirtualTargetsCorrected`의 가상 타겟 재투영 보정으로는 구조적으로 해결할 수 없어, **조준축 자체를 실제 시선축으로 설정**하는 방식으로 전환했습니다.

## 주요 변경사항

### 1. 시선축 자동 검출 및 aimAxis 설정 (autoDetectEyeAimAxis)

- 초기화 시 눈/머리 본마다 1회 **실제 시선축을 검출**하여 `MultiAimConstraint`의 `aimAxis`/`upAxis`/`worldUpType`을 본에 맞게 설정하고 리그를 rebuild
- 정렬된 리그(로컬 +Z = 시선)는 변경 없음 → 회귀 없음, rebuild도 일어나지 않음
- 꼬인 리그는 시선과 가장 가까운 카디널 로컬 축을 조준축으로 스냅(예: `aimAxis=Y`, `upAxis=Z_NEG`, `worldUpType=SceneUp`)
- `[SerializeField] bool autoDetectEyeAimAxis`(기본값 `true`)로 노출 — 수동 튜닝 보존이 필요하면 끌 수 있음
- offset은 0으로 고정 — 잘 만들어진 눈 본의 시선은 카디널 축에 놓이므로 스냅된 조준축이 곧 시선축

### 2. 깨진 재투영 제거 (UpdateEyeVirtualTargetsCorrected)

- 켤레변환 기반 방향 보정 로직을 제거하고, 각 눈의 가상 타겟을 **실제 타겟 위치에 직접 배치**(per-eye, 최소 거리 클램프 유지로 양 눈 수렴 보존)
- 조준축이 곧 시선축이 되므로 "조준 = 응시"가 성립 → 상하·좌우 모두 정상 추적
- 매 프레임 재투영 연산 제거로 런타임 비용도 감소
- `initialLeftEyeLocalRotation`/`initialRightEyeLocalRotation`은 BlendShape 경로에서 계속 사용하므로 선언/대입은 유지

### 3. 인스펙터 UX 정리

- Eye Control Strategy 드롭다운을 **`Blend Weight (Fluentt)` / `Transform`** 2개 항목으로 단순화 (`TransformCorrected`는 enum에 유지하되 UI에서 숨김)
- 기존 prefab의 `TransformCorrected`/`Transform` 값은 모두 "Transform"으로 표시하며, 사용자가 드롭다운을 직접 바꾸지 않는 한 재기록하지 않음(저장값/동작 보존)
- Transform 분기에 **"Auto-correct Eye Aim Axis"** 체크박스 추가(기본 ON), 눈 본 꼬임 감지 시 정보/경고 HelpBox 및 활성화 버튼 표시

## 호환성

- **하위 호환**: prefab에 저작된 제약 축을 init에서 덮어쓰지만, 정렬된 리그는 변경 없음(회귀 없음). 수동 튜닝 보존이 필요하면 `autoDetectEyeAimAxis = false`로 설정
- enum `EEyeControlStrategy.TransformCorrected`는 유지되어 기존 직렬화 값과 호환
- head 추적도 동일 축 가정을 사용하므로 동일 검출이 적용됨

## 검증 필요

- 원 수정은 `AvatarControllerSample`에서만 플레이모드 검증됨. FloatingHead 변형(머리 전용 아바타)은 테스트 씬에서 별도 플레이모드 검증을 수행해야 함
