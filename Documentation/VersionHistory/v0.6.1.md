# v0.6.1 - BlendShape 눈 제어 경로의 힙 할당 제거 (ACS v0.6.1 미러링)

**릴리스 날짜**: 2026-07-13

`BlendWeightFluentt` 눈 전략의 매 프레임 실행 경로에서 **힙 할당을 0으로** 만들었습니다. 동작 변경은 없습니다.

## 배경

룩타겟 시스템 전체를 감사한 결과, 매 프레임 힙 할당을 하는 코드는 `LookTargetController.EyeBlendShape.cs` 한 곳뿐이었습니다. 나머지(`Vector3.Lerp`, 쿼터니언 연산, Transform 대입)는 전부 할당이 없습니다.

```csharp
// 매 프레임, 블렌드쉐이프 항목마다 새 문자열을 만들어 딕셔너리를 조회하고 있었다
string key = $"{keyPrefix}_{item.skinnedMeshRenderer.GetInstanceID()}_{item.blendShapeIdx}";
float prevValue = eyeBlendShapePrevValues.GetValueOrDefault(key, 0f);
```

`ContainsKey` 가드가 있었지만 그것은 딕셔너리 *쓰기*만 막을 뿐, **검색용 키 문자열 자체의 할당은 막지 못합니다.** BlendWeightFluentt 아바타 1개당 프레임당 문자열 16개 + 딕셔너리 연산 24회 + `GetInstanceID` ICall 16회가 발생했고, 페이드아웃 완료 처리에는 `.Keys.ToList()` LINQ 할당까지 있었습니다.

IL2CPP/WebGL의 Boehm GC는 비세대·비압축이라, 이런 정상 상태(steady-state) 할당은 곧바로 주기적인 GC collection 스파이크로 이어집니다.

## 변경 사항

### 스무딩 상태를 항목 자신에게 (핵심)

`Dictionary<string, float> eyeBlendShapePrevValues`를 제거하고, `EyeBlendShape` 클래스에 런타임 상태 필드를 직접 넣었습니다.

```csharp
public class EyeBlendShape
{
    // ... 기존 직렬화 필드 ...
    [NonSerialized] public float prevValue;
    [NonSerialized] public bool prevInitialized;
}
```

문자열 키 생성, 딕셔너리 조회, `GetInstanceID` 호출이 전부 사라집니다. 페이드아웃 완료 판정도 8개 리스트를 직접 순회하도록 바꿔 `.Keys.ToList()` LINQ 할당을 제거했습니다(`List<T>`의 `foreach`는 struct enumerator를 쓰므로 할당이 없습니다).

`[NonSerialized]`이므로 프리팹 YAML과 커스텀 인스펙터 드로어에는 아무 영향이 없습니다.

### `Tuple` → `ValueTuple`, 죽은 `out` 파라미터 제거

`Tuple<Quaternion, Quaternion>`은 **클래스**라 호출마다 힙에 할당됩니다. `(Quaternion, Quaternion)` ValueTuple(struct)로 교체했습니다. "이번 프레임엔 각도 없음"을 표현하던 `null` 센티널은 `(Quaternion, Quaternion)?`(Nullable ValueTuple, 역시 struct)로 대체했습니다 — 그냥 ValueTuple로 바꾸면 `default`가 0으로 채워진 쿼터니언 4개가 되어 실제 회전값으로 조용히 읽히기 때문입니다.

`GetTargetEyeLocalRotation`의 `out quatForEyeTransform`은 유일한 호출부가 `out _`로 즉시 버리고 있었습니다(Transform 눈 전략은 직접구동 솔버가 담당하며 여기서 오지 않습니다). 파라미터와 함께 그것을 계산하던 코드도 죽은 코드가 되어 삭제했습니다 — `InverseTransformDirection` 2회, 쿼터니언 곱 4회, `LookRotation` 2회가 딸려 나갔습니다.

## 의도적으로 하지 않은 것

**수렴 후 `SetBlendShapeWeight` no-op write 스킵.** 값이 안 변했으면 쓰기를 건너뛰는 최적화는 하지 않았습니다. 이 write는 **의도적인 last-writer**입니다 — Talkmotion의 `ApplyFaceBlendShapeTransition`이 전환 중 얼굴 렌더러의 모든 블렌드쉐이프를 eyeLook 인덱스까지 무차별로 덮어쓰므로, write를 스킵하면 TM이 밀어넣은 값을 되돌릴 주체가 사라져 눈이 튑니다. 반대축에 0을 쓰는 것도 낭비가 아니라 길항 셰이프를 눌러 끄는 **기능**입니다. 코드에 주석으로 명시했습니다.

## 성능

- **GC**: 이 경로의 매 프레임 힙 할당이 0이 됩니다. 절대 절감량은 동시 활성 아바타 수에 비례하므로 자릿수 추정만 가능합니다 — 실제 수치는 Profiler의 GC Alloc으로 측정하십시오.
- **CPU**: 프레임의 0.1~0.5% 수준으로 크지 않습니다. 이 변경의 근거는 CPU가 아니라 **GC 쓰레기 제거**입니다.

## Breaking Changes

없음. `eyeBlendShapePrevValues`는 private 필드였고, `GetTargetEyeLocalRotation` / `StaringIntoSpaceEye` / `ApplyBlendShapeValues`는 private 메서드입니다. 계산 결과는 비트 단위로 동일합니다.
