# v0.6.0 - 가상 타겟을 아바타 계층으로 내장 (ACS v0.6.0 미러링)

**릴리스 날짜**: 2026-07-13

룩타겟(머리·눈 조준)의 가상 타겟을 **씬 루트의 전역 `VirtualTargets` 컨테이너**에서 **각 아바타 루트의 직속 자식**으로 옮겼습니다. AvatarControllerSample v0.6.0과 동일한 변경입니다.

## 배경

가상 타겟이 씬 루트에 있어야 했던 이유는 구(舊) `MultiAimConstraint`가 소스 오브젝트를 리그 바깥에 요구했기 때문입니다. 그 Animation Rigging 의존성은 v0.5.0에서 제거되었고, 남은 씬 루트 배치는 유물이었습니다. 그 유물이 만들어낸 실제 버그가 반복적으로 수정되어 왔습니다 — 클론 아바타 2개가 같은 이름 그룹을 공유하거나, 파괴 시 그룹이 누수되거나, 한 아바타가 다른 아바타의 그룹을 지우는 문제입니다.

가상 타겟은 **응시 대상이 아닙니다.** 실제 응시 대상은 씬의 `lookTarget`이고, 솔버는 `lookTarget.position`을 직접 읽습니다. 가상 타겟은 그 좌표로 수렴하는 **시간 스무딩 프록시**일 뿐이며, 수렴 목표값이 아바타와 무관하므로 부모가 아바타로 바뀌어도 "아바타가 회전하면 시선도 같이 돈다"는 동작 변화는 발생하지 않습니다.

**FloatingHead 특이사항**: FH 아바타는 `BlendWeightFluentt` 눈 전략을 쓰고 머리 제어가 꺼져 있습니다. 세 눈 전략 중 가상 타겟을 매 프레임 실제로 읽는 유일한 경로가 `BlendWeightFluentt`이므로, 이번 변경의 회귀 검증은 반드시 FH 아바타로 수행해야 합니다.

## 변경 사항

### 계층 구조

```
아바타 루트 (Animator, FluentTAvatarControllerFloatingHead)
├─ head_grp / Armature (본 계층 — 변경 없음)
└─ FT_VirtualTargets            ★신규: 루트 직속 자식, 빈 GameObject, 리프
    ├─ FT_LookAnchor_H          (구 HeadVirtualTarget)
    ├─ FT_LookAnchor_E          (구 EyeVirtualTarget)
    ├─ FT_LookAnchor_L          (구 LeftEyeVirtualTarget)
    └─ FT_LookAnchor_R          (구 RightEyeVirtualTarget)
```

씬 루트에 `VirtualTargets` 컨테이너가 더 이상 생성되지 않습니다.

### 이름 변경 (필수)

가상 타겟 이름에서 본 이름 토큰(`Head` / `LeftEye` / `RightEye`)을 제거했습니다. Talkmotion SDK의 본 탐색(`TMUtil`)은 정확 일치에 실패하면 **대소문자 무시 `Contains` 부분일치**로 폴백하는데, 서버 클립의 커브 경로가 `"Head"`이고 `"HeadVirtualTarget".Contains("Head")`가 참이므로, 구 이름 그대로 아바타 서브트리에 넣으면 **진짜 Head 본 대신 가상 타겟이 잡혀 머리 애니메이션 커브가 가상 타겟에 쓰일 수 있습니다.** 이름 상수는 `LookTargetController`에 단일 정의(`VirtualTargetsContainerName`, `HeadAnchorName`, `EyeAnchorName`, `LeftEyeAnchorName`, `RightEyeAnchorName`)로 모았습니다.

### 스무딩 상태를 필드로 분리

`Vector3.Lerp(vt.position, targetPos, ...)`가 가상 타겟 자신의 월드 위치를 매 프레임 시드로 재독출하고 있었습니다. 부모가 아바타가 되면 아바타의 이동·회전이 이 시드를 끌고 가 회전 중 시선이 뒤처집니다(2m 거리, `eyeSpeed=10`, 90°/s 회전 기준 약 9°). 스무딩된 월드 위치를 `LookTargetController`의 필드에 보관하도록 바꿔 부모 무관하게 만들었습니다 — 눈 솔버가 이미 쓰던 `smoothedDir` 패턴과 동일합니다. 함께 `Mathf.Clamp01(speed * deltaTime)`을 추가해 저프레임에서의 오버슛도 막았습니다.

### 버그 수정

- **`EnsureVirtualTargetRefs()` 조기 return 게이팅**: 조건이 `hasHeadRef &&`로 시작해 `enableHeadControl`을 보지 않았습니다. **FH 아바타 프리팹은 전부 머리 제어가 꺼져 있어** 헤드 ref가 영원히 null이었고, 따라서 조기 return이 한 번도 성립하지 않아 매 초기화마다 컨테이너 생성 경로를 탔습니다. 비활성 기능은 ref를 요구하지 않도록 게이팅을 고쳤습니다.
- **`CleanupVirtualTargets()` 제거**: 컨테이너가 아바타의 자식이므로 아바타와 함께 파괴됩니다. 기존 구현은 `GameObject.Find` + `(Clone)` 이름 매칭이라 동일 프리팹 클론끼리 서로의 그룹을 파괴할 수 있었고, 에디트 모드에서 호출되면 `Destroy may not be called from edit mode` 에러가 났습니다. `OnDestroy`의 호출부도 함께 제거했습니다.
- **`LookTargetController.FindVirtualTargets()`**: 전역 `GameObject.Find("VirtualTargets")`를 아바타 자기 하위 조회로 교체했습니다. 아바타마다 컨테이너를 갖는 구조에서 `GameObject.Find`는 씬 전역·매칭 순서 미정의 탐색이라 다른 아바타의 타겟을 조용히 반환할 수 있습니다.

## 스키닝 안전성

가상 타겟은 **컴포넌트 없는 빈 GameObject를 리프로만** 추가합니다. `SkinnedMeshRenderer.bones`는 Transform 참조 배열이고 bindpose는 임포트 시점에 고정되므로, 리프 추가는 스키닝 바인딩·본 인덱스·저작 클립의 경로 바인딩을 한 글자도 바꾸지 않습니다. 지켜야 할 규칙은 두 가지입니다.

- **본/Armature/메시 노드 하위에 두지 말 것.** 특히 애니메이션되는 head 본 하위에 두면 머리가 자기 조준 타겟을 끌고 다니게 됩니다. MagicaCloth의 `rootBones` 서브트리에 들어가면 클로스 파티클로 자동 수집됩니다.
- **기존 본이나 메시를 가상 타겟 하위로 재부모화하지 말 것.** 리프 추가와 달리 경로·깊이가 바뀌어 클립 바인딩이 깨집니다.

## Breaking Changes

- 공개 API 변경 없음. `CleanupVirtualTargets()`는 private였습니다.
- 씬·프리팹 마이그레이션 불필요: 기존 씬·프리팹 어디에도 `VirtualTargets` 오브젝트가 저장되어 있지 않고, 직렬화된 `*VirtualTargetRef` 4개가 전부 비어 있어 실행 경로는 100% 런타임 생성뿐이었습니다.
- 가상 타겟을 이름으로 찾던 외부 코드가 있다면 새 이름(`FT_VirtualTargets` / `FT_LookAnchor_*`)과 새 위치(아바타 하위)로 갱신해야 합니다.
