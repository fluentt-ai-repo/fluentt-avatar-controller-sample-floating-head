# v0.4.0 - Look Target 통합 캘리브레이션 조준 (AvatarControllerSample v0.4.0 포팅)

**릴리스 날짜**: 2026-07-10

`AvatarControllerSample` v0.4.0의 **레스트(bind) 포즈 캘리브레이션 기반 직접구동 솔버**를 FloatingHead 변형에 포팅했습니다. 이로써 두 패키지의 Look Target 로직이 동등해집니다.

> 원 분석·구현·실측 검증(호환성 씬 11개 아바타, 16-에이전트 적대적 리뷰)은 `AvatarControllerSample`에서 수행됐습니다. 상세 배경은 [ACS v0.4.0 릴리스 노트](../../../AvatarControllerSample/Documentation/VersionHistory/v0.4.0.md)를 참고하세요. **FloatingHead 변형은 별도 플레이모드 검증이 필요합니다** (§검증 필요).

## 포팅 배경 — FloatingHead가 뒤처져 있던 지점

v0.3.4까지 FloatingHead는 다음 세 가지가 ACS와 달랐습니다.

| 항목 | v0.3.4 (이전) | v0.4.0 (현재) |
|---|---|---|
| **머리 조준** | 100% `MultiAimConstraint` — 직접구동 솔버 없음 | `EHeadAimMode.DirectCalibrated`(기본) 직접구동 |
| **눈 스무딩** | `eye.rotation = Slerp(eye.rotation, targetRot, t)` — **미수렴** | 지속 방향 필드 `_left/_rightEyeSmoothedDir` 스무딩 |
| **캘리브레이션 기준축** | `lookHead.forward` — **자기참조** | 아바타 루트 `transform.forward` |

## 주요 변경

### 1. 머리: `EHeadAimMode` 신규 (기본 `DirectCalibrated`)

`MultiAimConstraint` 머리 경로는 "머리 본의 로컬 +Z = 얼굴 정면"을 가정합니다. Rigify 계열(DEF-spine.005)은 본 +Z가 얼굴 정면 대비 7.4944° 아래로 기울어 있어, 컨스트레인트가 +Z를 타겟에 꽂는 순간 얼굴이 그만큼 위를 봅니다.

- bind 포즈에서 머리 본의 실제 얼굴 정면/업을 **아바타 루트 기준으로 1회 측정**(`CaptureLookAimBindPose`) 후, 매 `LateUpdate`에 애니메이션 포즈 위로 **최단호 보정 회전**을 얹어 직접 구동
- **조준 원점 = 눈 중심** → 피벗-눈 시차 제거 (1m 근거리에서 ~6.5° 추가 오차였음)
- `headAngleLimit` 클램프 · `headSpeed` 스무딩 · 비활성화 시 identity로 페이드
- 머리 `MultiAimConstraint`는 init에서 `weight=0` (리그는 유지 → `Constraint` 모드로 복귀 가능)
- `SyncHeadAimMode()`가 매 프레임 모드↔weight를 동기화하여 **플레이 중 모드 전환** 지원. Direct→Constraint 전환 시 `SnapHeadVirtualTargetToTarget()`으로 정지해 있던 가상 타겟을 타겟 위로 올려 첫 프레임 스윙 방지

### 2. 눈 추적 미수렴 수정 (v0.3.4부터 있던 선재 버그)

`AimSingleEyeUniversal()`이 **최종 본 회전**을 스무딩하고 있었습니다. Animator가 매 프레임 눈 본을 다시 쓰므로 `eye.rotation`이 매번 애니메이션 포즈로 리셋되고, Slerp가 누적되지 못해 **매 프레임 필요 각도의 `t = eyeSpeed × deltaTime` 비율만** 따라갑니다. 결과적으로 눈이 타겟에 못 미친 채 정착하며, **프레임레이트가 높을수록 오차가 커집니다**.

- `_leftEyeSmoothedDir` / `_rightEyeSmoothedDir`(월드 공간)를 필드로 유지 → 애니메이션 리셋과 무관하게 수렴
- 스무딩 후 회전은 Slerp 없이 곧바로 기록
- `eyeTransformAngleLimit` 클램프를 스무딩 **전·후** 두 번 적용
- `_eyeAimDrivingLastFrame`으로 구동 재개를 감지 → 재개 시 현재 애니메이션 포즈에서 시드(램프인, 스냅 없음)
- `eyeSpeed == 0`은 "눈 추적 안 함"으로 처리해 구동 자체를 스킵 (`t == 0`이면 첫 시드 방향에 눈이 영구히 얼어붙음)

### 3. 눈: `EEyeAimMode.Auto` = 항상 직접구동

기존 `Auto`는 "미러 본일 때만 직접구동"이었으나, 직접구동 솔버가 어떤 축 방향에도 정확하므로(비카디널 시선축 포함) **항상 직접구동**으로 변경. `Constraint`는 레거시 폴백으로 유지.

### 4. 기준축 자기참조 수정

- `CalibrateUniversalEyeAim`·`CalibrateHeadAim`의 레스트 시선 기준: `lookHead.forward` → **아바타 루트 forward**
- `DriveUniversalEyeAim`의 눈 클램프 기준: 머리 본 +Z → **캘리브레이션된 얼굴 정면**(`CurrentHeadGazeDirection()`)
- `AutoConfigureLookAimAxes`(Constraint 폴백용)·Editor `DrawEyeTwistDiagnostics`의 gazeRef도 루트 forward로 수정

### 5. 라이프사이클 버그 수정 (FloatingHead 고유)

- **`OnEnable` 재구독 누락**: `OnDisable`이 `OnLateUpdateCompleted` 구독을 해제하는데 재구독은 `Start`에만 있어, 컨트롤러를 껐다 켜면 **룩타겟이 영구히 죽었습니다.** `OnEnable`에서 멱등(`-=`/`+=`) 재구독하고, 이중 구독을 막기 위해 `Start`의 구독도 멱등으로 변경
- **`LateUpdate` 폴백**: 직접구동 패스는 `FluentTAvatar.OnLateUpdateCompleted`에서 실행되는데, FluentTAvatar가 비활성인 아바타는 이벤트가 발화하지 않아 추적이 중단됩니다. `avatar == null || !avatar.isActiveAndEnabled`일 때 컨트롤러 자체 `LateUpdate`에서 실행하는 폴백 추가
- **`ResetLookAimSmoothing()`**: 룩타겟 off 및 `OnDisable`에서 머리 보정 + 눈 스무딩 상태를 리셋. 두 솔버의 상태는 월드 공간 절대값이라 구동이 멈춘 동안 낡아지고, 재활성화 첫 프레임에 본이 튑니다

### 6. `CleanupVirtualTargets` 그룹 누수 수정 (선재 버그, 적대적 리뷰에서 발견)

가상 타겟 그룹은 생성(`RuntimeFindOrCreateAvatarVirtualTargetGroup`)·탐색(`LookTargetController.FindVirtualTargets`) 시 아바타 이름에서 `(Clone)`을 제거하는데, **삭제(`CleanupVirtualTargets`)만 원본 이름을 사용**하고 있었습니다. 런타임 `Instantiate`된 아바타를 파괴하면 `{name}_VirtualTargets` 그룹을 찾지 못해 씬에 누적됩니다. ACS와 동일하게 `(Clone)`을 제거하도록 수정했습니다.

### 7. 죽은 작업 제거 (성능)

직접구동이 본을 소유하면 해당 `MultiAimConstraint`는 `weight=0`이므로 가상 타겟을 아무도 읽지 않습니다.

- `LookTargetController`에 `headDirectDriven`/`eyeDirectDriven` 플래그 추가 → 해당 본의 가상 타겟 `Vector3.Lerp` 스킵
- `ApplyAngleLimitsToConstraints()`는 직접구동이 소유한 본을 건너뜀
- **`BlendWeightFluentt`는 예외**: `EyeBlendShape.cs`가 방향 계산에 `eyeVirtualTarget`을 읽으므로 계속 갱신 (이 전략은 결코 직접구동되지 않음)
- 눈 소유권은 단일 프로퍼티 `EyesDirectDriven`(= `_eyeAimCalibrated && 전략 != BlendWeightFluentt`)로 통일
- **기즈모**: 직접구동 본의 정지한 가상 타겟은 런타임에 그리지 않고, 대신 실제 조준선(눈 중심/양눈 → 타겟)을 그림

## 호환성

- **하위 호환**: 기존 씬/프리팹은 `headAimMode` 직렬화 값이 없어 `DirectCalibrated`(enum 0)로 동작 — 의도된 기본값
- `EEyeAimMode`는 **멤버 순서를 바꾸지 않았으므로** 기존 직렬화 값과 호환. 다만 `Auto`(=0)의 **의미가 바뀝니다**: 정상(비미러) 리그도 이제 직접구동됩니다. 레거시 동작이 필요하면 `Constraint`를 명시 선택하세요
- 기존에 저작된 `MultiAimConstraint` 리그 구조는 그대로 유지되며 (`weight=0`) `Constraint` 모드 선택 시 기존 동작으로 복귀
- `autoDetectEyeAimAxis`는 `Constraint` 모드에서만 의미 (UI도 해당 모드에서만 노출)

## 검증 (AvatarCompatibilityTest 씬, `260105_taerin_rig`, 플레이모드 실측)

- ✅ **컴파일 클린** (Unity 6000.4.3, 신규 경고 0건)
- ✅ 포팅 diff에 대한 멀티에이전트 적대적 리뷰 수행

검증 아바타는 이 저장소에서 FloatingHead 컨트롤러를 쓰는 **유일한** 아바타인 `260105_taerin_rig`입니다. `headAimConstraint = null`, `eyeControlStrategy = BlendWeightFluentt` 조합입니다.

> **이 아바타는 v0.3.4까지 머리 추적을 쓸 수 없었습니다.** `headAimConstraint`가 없으므로 `enableHeadControl`을 켜는 순간 `InitializeLookTarget()`이 `LogError` 후 `return`하여 룩타겟 초기화 전체가 중단되고 눈 추적까지 죽었기 때문입니다. v0.4.0은 그 검사를 `Constraint` 모드로 한정하므로, **constraint 없이 머리를 직접구동할 수 있습니다.**

측정 조건: 타겟을 눈 중심 기준 **0.8m 거리 · 얼굴 정면에서 21.9° 비스듬히** 배치, ~178fps.

| 항목 | 결과 |
|---|---|
| 머리 조준 잔여 오차 (눈 중심 기준) | **0.0626° ~ 0.5189°** (idle 애니메이션 구동 중 수렴) |
| 피벗 기준 잔여 | 5.4861° — 차이 **4.977°가 정확히 피벗-눈 시차** (v0.4.0이 제거하는 오차) |
| `_headLocalGaze` | `(0,0,1)` — taerin은 머리 본이 루트와 완전 정렬된 리그 |
| bind 포즈 캡처 멱등성 | 모드 왕복 후에도 `_headLocalGaze` 불변 (애니메이션 포즈 오염 없음) |
| `headDirectDriven` / `eyeDirectDriven` | `True` / `False` — BlendWeight 눈은 직접구동되지 않음(정상) |
| `BlendWeightFluentt` 무회귀 | `EyeVirtualTarget`이 타겟과 거리 **0.00000m** — 죽은 작업 제거가 눈 경로를 죽이지 않음 |
| `OnLateUpdateCompleted` 구독자 수 | **1** (Start+OnEnable 이중 구독 없음 → 솔버 1회/프레임) |
| 컨트롤러 disable→enable | 구독자 `0 → 1` 복구, `_headAimCorrection`이 0으로 리셋 후 램프인 (**v0.3.4였다면 0에서 복구 실패**) |
| `DirectCalibrated` ↔ `Constraint` 왕복 | `headAimConstraint == null`에서도 예외 없음. 복귀 시 재캘리브레이션 후 잔여 0.4192°로 재수렴 |
| 콘솔 에러 | 0건 (`UnityEditor.Graphs.Edge.WakeUp` 예외는 Animator 그래프 에디터의 Unity 내부 이슈, 본 변경과 무관) |

### 남은 미검증 항목

- **머리 본 틸트 보정**: taerin은 머리 본 +Z가 루트 forward와 **0.0000°** 정렬된 리그라, doctor(7.49° 틸트) 같은 케이스의 보정 효과는 이 저장소에서 재현할 수 없습니다. 해당 경로는 ACS v0.4.0에서 실측 검증됐습니다
- **직접구동 눈 솔버**(`Transform`/`TransformCorrected` 전략): taerin이 `BlendWeightFluentt`라 미실행. 미수렴 수정과 `eyeSpeed == 0` 스킵은 ACS에서 검증됨 (aru @198fps: 2.343° → 0.0396°)

> ⚠️ 캘리브레이션은 **"bind 포즈가 아바타 루트 정면을 바라본다"**를 가정합니다. 저작 기본 포즈에서 머리가 실제로 돌아가 있는 아바타는 그 방향이 기준이 되므로, 그런 리그는 `Constraint` 모드 또는 리그 수정이 필요합니다.
