# v0.6.2 - 시선 랜덤 오프셋 매 프레임 재추첨 수정, TargetTracking 데드코드 제거 (ACS v0.6.2 미러링)

**릴리스 날짜**: 2026-07-13

룩타겟 감사 중 발견된 버그 1건과 v0.5.0 잔재 데드코드 1건을 정리합니다. 성능 변경이 아닙니다.

## 1. 시선 랜덤 오프셋이 매 프레임 재추첨되던 버그

`UpdateLookTarget()`은 인스펙터 변경이 즉시 반영되도록 매 프레임 `SetLookTargetSetting(idleLookSettings)`를 호출합니다. 그런데 `SetLookTargetSetting()` 안에서 `Random.Range`로 `quatEyeVariance`를 **매 호출마다 새로 추첨**하고 있었습니다.

```csharp
// 변경 전 — 매 프레임 새로 추첨된다
public void SetLookTargetSetting(LookTargetSetting setting)
{
    currentSetting = setting;
    if (setting != null)
    {
        Vector3 angle = setting.eyeAngleVariance;
        float randomPitch = UnityEngine.Random.Range(-angle.x, angle.x);
        ...
    }
}
```

`eyeAngleVariance`는 "아바타마다 시선을 조금씩 다르게 두는 **안정적인 랜덤 오프셋**"을 의도한 값입니다. 매 프레임 재추첨되면 오프셋이 아니라 **프레임 노이즈**가 되고, 눈 블렌드쉐이프의 `Mathf.Lerp` 스무딩이 이 노이즈를 평균 0으로 저역통과시켜 버려 **기능 자체가 성립하지 않습니다.**

현재 저장소의 모든 아바타 프리팹이 `eyeAngleVariance: {x: 0, y: 0}`이라 오늘 기준 관측 가능한 출력 차이는 없습니다 — identity 회전에 가려져 있을 뿐입니다. 누군가 값을 켜는 순간 눈이 떨립니다.

**수정**: 분산 **값**이 바뀔 때만 재추첨합니다. 설정 **참조**로 가드하면(`setting != currentSetting`) `idleLookSettings` 하나만 전달되므로 추첨이 평생 1회로 굳고, 플레이 중 인스펙터에서 값을 조정해도 영원히 반영되지 않습니다 — 그건 원래의 "인스펙터 변경 즉시 반영" 설계 의도를 깨뜨립니다.

## 2. TargetTracking 데드코드 제거

`transform.Find("TargetTracking")`와 `UpdateTrackingGameObjectStates()`는 Animation Rigging 시절의 유물입니다. `TargetTracking`은 아바타 루트 밑에 Rig와 MultiAim 컨스트레인트를 담고 있던 홀더 GameObject였고, 그 자식 `HeadTracking` / `LeftEyeTracking` / `RightEyeTracking`을 이 코드가 켜고 껐습니다.

v0.5.0에서 리깅을 제거하고 전 프리팹·씬에서 스캐폴딩을 걷어냈으므로, 이 `Find`는 **그 뒤로 한 번도 매칭되지 않았습니다.** 도달 불가능한 no-op이면서도 아바타당 프레임당 2회씩 계속 돌고 있었고, 삭제된 컨스트레인트를 설명하는 오정보 XML 주석까지 달고 있었습니다.

**성능 근거로 제거하는 것이 아닙니다.** early return 때문에 실제 비용은 아바타당 프레임당 `transform.Find` 2회(≈수 µs)뿐이고, 하위 `Find` 3회와 `SetActive` 호출은 한 번도 실행되지 않았습니다. 제거 가치는 코드 위생입니다.

**제거 대상**: `UpdateTrackingGameObjectStates()` 메서드 전체 + 호출부 4곳(`InitializeLookTarget`, `UpdateLookTarget`, `SetLookTargetEnabled`).

## Breaking Changes

- 레거시 `TargetTracking` GameObject의 자동 활성/비활성 제어가 더 이상 수행되지 않습니다. 소비 저장소 프리팹에 이 오브젝트가 남아 있어도 v0.5.0에서 컨스트레인트가 이미 삭제되어 `SetActive`가 아무 효과가 없으므로 실질 영향은 없습니다.
- 공개 API 시그니처 변경 없음. `SetLookTargetEnabled()`의 동작은 동일합니다.

## 검증

- 컴파일 에러 0.
- `eyeAngleVariance`를 (0,0)이 아닌 값으로 설정했을 때 시선 오프셋이 안정적으로 유지되는지(떨리지 않는지), 그리고 플레이 중 인스펙터에서 값을 바꾸면 즉시 재추첨되는지 확인 필요.
- (수동 테스트 결과 기록 예정)

## 후속 (미착수)

`LookTargetSetting.headAngleVariance`는 어디서도 읽히지 않는 완전 죽은 필드이고, `talkingLookSettings`도 `SetLookTargetSetting`에 전달되는 코드가 없어 "설정 전환" 경로 자체가 현재 죽어 있습니다. 직렬화된 공개 필드라 제거 시 마이그레이션이 필요하므로 별도로 다룹니다.
